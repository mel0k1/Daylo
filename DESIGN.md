# DESIGN

Заметки о внешнем виде лаунчера. Заполняется по мере работы над интерфейсом;
в README дизайн не упоминается.

## Принципы

- Тёмная тема по умолчанию, один акцентный цвет (синий #2b3fbd)
- Пиксельный стиль во всём: квадратные углы, двухпиксельные рамки, жёсткие
  тени со сдвигом, никаких скруглений и мягких градиентов
- Простые экраны без вложенных меню

## Шрифты

- Pixuf — логотип и заголовки (`.logo`, `.retro-title`). Пропорциональный
  пиксель-шрифт с ровной полной кириллицей, сетка кратна 8: заголовки 16px,
  логотип 24px. CC0 (erytau 2020), файл и копирайт в `src/assets/fonts`
- Press Start 2P остаётся фолбэком в `--font-pixel` на случай сбоя загрузки
- Pixelify Sans — весь остальной текст, включая кнопки и инпуты pixel-retroui
- Все с кириллицей, вшиты локально в `src/assets/fonts` (OFL/CC0-лицензии
  рядом), подключение в `src/styles/fonts.css`
- Компоненты pixel-retroui просят шрифт «Minecraft» без кириллицы — в
  fonts.css для него объявлен алиас на Pixelify Sans, чтобы надписи внутри
  кнопок и инпутов не рассыпались на system-ui
- Размеры пиксель-шрифта держим кратными 8 (16/24px): Pixuf на «некратной»
  высоте плывёт по сетке и выглядит неряшливо

## Текущее состояние

- Тёмная палитра и пиксельная тема в `src/styles/base.css`, фон — едва
  заметная шахматная сетка + атмосфера поверх неё (под контентом):
  ступенчатое «небо» сверху и затемнение над панелью (body::before,
  жёсткие полосы без мягких градиентов) и медленные пиксель-частицы
  снизу вверх (.bg-fx, параметры в App.tsx, выключаются при
  prefers-reduced-motion), квадратные скроллбары
- Нижняя панель: логотип с полоской «травы» и жёлтым сплэшем под углом
  (случайная фраза на каждый запуск, pulse-анимация, прячется на узком
  окне), травяная полоса во всю ширину над панелью (::before — верхний
  срез блока травы), пункты меню с цветными слот-иконками, чип аккаунта
  и номер версии справа
- Заголовки секций библиотеки несут слот-буллет в цвет слотов панели
  (.lib-section:nth-of-type), пустые состояния — крестик «слот без
  предмета» (.slot-cross), карточки при ховере сдвигаются на 1px
  (steps — пиксельно, без плавности)
- Кнопка «Играть» в топбаре — главная: зелёная (#2f7d4f, как все
  позитивные действия) и крупнее обычной (.btn-cta)
- Прогресс-бары живут: на заливке бегут пиксельные полоски (.pbar-fx
  на ProgressBar + .update-bar-fill), шаг steps(6) по полному периоду
  12px — движение рваное по-пиксельному, без плавности
- Темы оформления (`src/state/theme.ts` + блок «Темы» в base.css):
  тьма (по умолчанию), светлая («бумажный песчаник»), равнина
  (сумеречная зелень), ад (багровый кримсон-нилайум). Тема — чистый
  фронт: data-theme на <html> переопределяет весь блок переменных
  (включая pixel-retroui и цвета атмосферы/частиц/травы), хранится в
  localStorage, переключатель — карточка «Оформление» в настройках
  (работает без ядра). Сплэш в светлой теме темнее (--splash), трава
  в аду — кримсон (--grass-*)
- ИИ-сборщик («Сборки» → «ИИ-сборка»): описание сборки словами → бесплатный
  безключевой LLM-шлюз (text.pollinations.ai, OpenAI-совместимый) возвращает
  JSON-список модов → каждый запрос разрешается через поиск Modrinth →
  пользователь снимает галочки с лишних → создаётся сборка и моды ставятся
  по одному, сбои отдельных модов не роняют остальные. Движок:
  `engine/game/aibuild.rs`, источник менять в одном месте — константа LLM
- Экран «Играть»: карточка запуска, справа колонка с 3D-скином, серверами
  и карточкой новостей релизов
- 3D-скин (`src/components/SkinView.tsx`): модель из CSS-граней без WebGL —
  голова, тело, конечности, слои шляпы/куртки/рукавов/штанов, затенение
  граней, качание рук и ног, вращение мышью с авто-докруткой; старые скины
  64x32 нормализуются в 64x64 зеркалированием левых конечностей
- Экран «Моды»: вкладки «Мои моды» (список установленного всегда виден,
  пустое состояние со слот-крестиком) и «Каталог Modrinth» (поиск)
- Экран «Сборки» (`src/screens/Packs.tsx`): вкладки «Мои сборки» и «Каталог».
  Мои сборки — сетка карточек с обложкой, версией игры, тегом загрузчика и
  бейджами источника/памяти/числа модов; кнопки «Играть» и «Удалить» прямо в
  карточке, пустое состояние со слот-крестиком. Каталог — переключатель
  источников Modrinth / CurseForge / FTB, поиск с фильтром по версии игры,
  выбор версии сборки перед установкой, общий прогресс-бар установки
- Бейджи источников (`.pack-badge`) — верхний регистр, узкая рамка, тот же
  инсет-фон, что и у вкладок; источник повторяет стиль слот-иконок
- Экран «Моды»: вкладка «Каталог» получила переключатель Modrinth / CurseForge
  поверх поисковой строки, плейсхолдер меняется вместе с источником
- Прогресс установки сборки — общий блок с прогресс-баром над содержимым
  экрана: стадии распаковки/файлов/загрузчика/файлов игры приходят событиями
  ядра (pack-progress + install-progress)

## Ревизия стилей

- Цвета состояний вынесены в переменные: `--bg-hover` (инсет-ховер,
  выпадашки и тайлы), `--ok` (успех/зелёный акцент), `--danger` (ошибки и
  удаление), `--link` (ссылки) — литералы в правилах заменены на var()
- Единые правила на весь интерфейс: `button:disabled` (opacity .55, курсор
  по умолчанию), плейсхолдеры инпутов и textarea в `--muted`, уголок
  скроллбара в цвет трека (`scrollbar-corner`)
- Пиксельный шрифт заголовков подрос на 1px без потери сетки: `.retro-title`
  13px, `h1.retro-title` 16px, `.logo` 18px — Press Start 2P при 12px читался
  с трудом на нецелых масштабах webview

## Обновление лаунчера

- Стейт обновления живёт в общем zustand-сторе `useUi` (ver, update,
  progress, updateError), а не в локальных useState App: карточку в
  настройках и баннер в сайдбаре наполняет один источник
- Слушатель прогресса ставится один раз на всю сессию (`updateInit` с
  защитой от повторного входа в StrictMode), свежая версия проверяется
  сразу при старте
- Карточка «Обновление» в настройках: версия и размер в МБ, сводка релиза
  без markdown-разметки (3 строки), прогресс-бар скачивания, зелёная кнопка
  «Установить и перезапуститься», ручная «Проверить сейчас»

## Сравнение с Millida Launcher

Millida (millida.net) — ближайший конкурент, тоже GPL-3.0 с открытым
репозиторием. Сверялись, чтобы не изобретать велосипед и честно понимать,
что переносим, а что нет.

Совпадает (база любого лаунчера):

- Ванила + Fabric/Forge/Quilt/NeoForge, авто-докачка Java и библиотек
- Зеркала для загрузок из России (у нас BMCLAPI, у Millida своё зеркало)
- Скины и авторизация не только через Mojang
- Каталоги модов и сборок с поиском

Сознательно не берём:

- Экосистему вокруг лаунчера: друзья, голосовой чат, донат-сервер,
  внутренняя валюта, витрина серверов с оплатой — это отдельный бизнес, а
  не лаунчер, и тянет за собой серверную часть с аккаунтами
- Проприетарные облачные сохранения — пока без серверной инфраструктуры

Перенято по духу (у Millida удобно, у нас сделано по-своему):

- Карточка обновления с человеческой сводкой релиза вместо голой ссылки
- Своя сборка в два клика (версия + загрузчик) без ручного импорта
- Пометка источника мода, чтобы обновлять Modrinth и CurseForge по-разному

Своё, чего у Millida нет:

- Краш-модал с расшифровкой причины по-русски и советами, прямо из лога
- Оффлайн-режим без обязательного аккаунта, вход Ely.by и Microsoft рядом
- Автообновление самого лаунчера через GitHub Releases с gh-прокси для РФ
